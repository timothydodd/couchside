# CLAUDE.md

Couchside is a self-hosted media server for k3s. Go backend in `server/`, React frontend in `web/`, Helm chart in `deploy/helm/couchside`. The UI shares `../portside-lite`'s component classes and shell layout; its colours come from the C logo (see `docs/style.md`).

## Build & verify (WSL)

- Go 1.26 is required by `modernc.org/sqlite`. `~/.local/go/bin/go` is 1.23, but GOTOOLCHAIN=auto downloads 1.26 on first use.
  `cd server && ~/.local/go/bin/go vet ./... && ~/.local/go/bin/go test ./...`
- npm on `/mnt/f` is slow. Copy `web/` (without node_modules) to the session scratchpad, then run `npm install && npx tsc --noEmit && npx vite build` there. Copy `package-lock.json` back if it changed.
- Full-stack smoke test: build the binary, then run it with `COUCHSIDE_DATA_DIR`, `COUCHSIDE_MEDIA_ROOT` and `COUCHSIDE_WEB_DIR=<scratch>/web/dist`. Generate sample media with `ffmpeg -f lavfi -i testsrc2=...`.
- Docker builds and the real deploy run from Windows.
- **Embedded UI**: `server/internal/webui` embeds `dist/`, which is only a `.gitkeep` in git. The Dockerfile and release workflow copy `web/dist` there before `go build`. `COUCHSIDE_WEB_DIR` overrides it with a folder on disk.
- **Website**: `site/` (static HTML, the logo's tokens from `docs/style.md`) is published to https://couchside.app by `.github/workflows/pages.yml`, which copies the icons in from `web/public`. The custom domain is set in the repo's Pages settings.
- **Releases**: push a `v*` tag. `.github/workflows/release.yml` builds zips (linux/darwin amd64 and arm64, windows amd64), a multi-arch ghcr image, and a GitHub Release with SHA256SUMS. `ci.yml` runs vet, test and the web build on pushes and PRs; `docker.yml` builds the image (amd64, no push) when the Dockerfile changes. A release runs vet and test first (`verify`), and the container waits for the web build. Third-party actions are pinned by commit SHA (version in a comment) and base images by digest; Dependabot updates both. Comskip is cloned by tag and checked against `COMSKIP_COMMIT`. Icons live in `web/public/icons/logo-<size>.png`, plus `favicon.ico`, `apple-touch-icon.png` and `site.webmanifest`. They're generated from `branding/logo-c-original.png` by `python3 branding/make-icons.py` (Pillow): the C is re-centred on its navy, rounded tiles for 64px and up (C at 72%), a bigger C for 16/32/48 and the .ico (86%), and a full-square apple-touch-icon because iOS rounds it itself. `branding/make-transparent.py` cuts the C out onto transparency (`branding/logo-c-transparent.png`).

## Architecture

- **One process, one pod.** The HTTP API and worker pool share a SQLite database in WAL mode. The Deployment uses `strategy: Recreate` because the DB sits on a ReadWriteOnce PVC. Don't scale replicas.
- **Job queue** is the `jobs` table. A partial unique index dedupes active jobs, and `ClaimJob` runs `UPDATE ... RETURNING` in priority order: scan, match, artwork, still. The encode pool takes `optimize` and `commercials` (`encodeKinds` in `db/jobs.go`), commercials first. Kinds are defined in `internal/worker/worker.go`.
- **Scan flow:** walk, then `parse.Movie`/`parse.Episode`, then `probe.Probe`, then upsert. A newly created item enqueues `match`, which enqueues `artwork`. TV files enqueue `still`. Pruning uses `files.last_seen < scanStart` and is skipped, failing the job, when any folder or file couldn't be read or when the walk found no videos in a library that has files (an unmounted share).
- **Parsing** (`internal/parse`) covers S01E02 with seasons up to 4 digits, 1x02, Plex-DVR date names (`Show - 2024-11-10 03 30 00 - Title.ts`), and bare E01 files. Date names become episode `YYMMDDHHMM` plus `episodes.air_date`. Unchanged files are re-parsed every scan (no probe), and re-indexed if the parse changed, so parser fixes reach existing libraries.
- **Matching** never trusts a provider's fuzzy title lookup. `metadata.pickBest` scores candidates from exact lookup with and without year, plus search with and without year, on normalized title and year. Title variants ("3.10" to "3:10", " - " to ": ", "&" and "and") are tried when the result is missing or only partial. `imdb_pinned` marks "Fix match" choices, which automatic re-matches keep.
- **Unplayable files** get `files.problem` (`unreadable` or `no-video`, usually DRM iTunes files). They get no stills, optimize or HLS, and the UI explains why.
- **Grouping key** is `(library_id, kind, parsed_title, parsed_year)`, where `parsed_year` is 0 when unknown. Metadata overwrites `title`, but grouping always uses the parsed fields.
- **File roles** (movies only; `files.role`, `part_no`, `extra_title`, `role_pinned`): `copy` (default; extra copies are duplicates), `part` (a movie split across files) or `extra` (bonus material). `parse.MovieRole` guesses from the path relative to the library root: an extras folder inside a movie folder (`Featurettes/`, `Trailers/`…; at the root it's just a folder of movies), a Plex suffix (`-trailer`), an extras word (`Behind the Scenes`), or a part marker (`Part 2`, `cd1`, `Disc Two`). Markers that are in the parsed title (`Deathly Hallows Part 2`, `The-Big-Short`) don't count. The scan uses `MovieIn`/`MovieRoleIn` with a folder lister (`videosIn`): an extras folder counts only under a folder named like a film with a year or holding a film file (`Pixar/Shorts` is a folder of films), and a part marker only when another file beside it has one. TV skips extras-named folders except directly under the root (a show called "Extras"); sample clips are `sample`, a `-sample`/`.sample` suffix, or anything in a `Sample` folder, under 300 MB. `refreshRole` applies the guess to unchanged files on every scan unless `role_pinned`. `PUT /api/files/{id}/role` pins a hand-picked role; marking part 2+ with no part 1 makes the item's single other copy part 1. Extras aren't counted in `fileCount`/`watchedCount`, "mark watched", backdrops or duplicate counts, get stills, and play as "Movie - Extra". `PlayInfo.parts` lists the parts (best copy of each); the player draws one timeline across them (`Timeline.parts` in `PlayerFrame`), seeks across parts by navigating with a module-level `partStart`, and always continues into the next part.
- **Settings → right now** (`GET /api/system`, `api/system.go`, `web/src/components/settings/ServerNow.tsx`): CPU and memory come from `internal/sysstat` (cgroup v2 `cpu.stat`/`cpu.max`/`memory.current` minus `inactive_file` when `memory.current` exists, otherwise `/proc/stat` and `/proc/meminfo`; per-process CPU from `/proc/<pid>/stat` for Couchside and its `ffmpeg`/`comskip` children). CPU is averaged since the previous call, or over a 250ms pause when that was more than 10s ago. Non-Linux reports `available: false`. Who's connected is in-memory (`api/presence.go`): a client is profile + IP + user agent, touched by every `/api` request (the status poll keeps it alive, 75s window). Playing state comes from progress reports, which now carry `state` (`playing`/`paused`/`stopped`) and `mode`; live TV and recordings are set by `tvWatch`/`dvrWatch` and kept alive by playlist polls.
- **Metadata providers** implement `metadata.Provider` and run in order through `metadata.Chain`: TMDB (`metadata/tmdb.go`) first, OMDb as a fallback. Responses are cached in `provider_cache` (TMDB TV for 3 days, the rest 30). Not-found answers are cached; bad-key, rate-limit and quota errors are not. The IMDb id stays the item's identity: TMDB fills `Details.ImdbID` from `external_ids`, resolves IMDb ids through `/find`, and uses `tmdb:movie:<n>` / `tmdb:tv:<n>` (`metadata.TMDBID`) for titles IMDb lacks; OMDb ignores those. TMDB backdrops land in `media_items.backdrop_url` and the artwork job downloads them, grabbing a video frame only when there's none. The TMDB key: `TMDB_API_KEY` (`off` disables), else `config.builtinTMDBKey`, stamped by `-ldflags -X` in release builds from the `TMDB_API_KEY` repo secret (a Docker build secret, never a build arg). `/api/status` reports `tmdbKey` (builtin/custom/""). TMDB requires the attribution line and logo (`web/public/brand/tmdb.svg`) shown in Settings → Metadata and on the website.
- **Artwork** lives in `$CACHE/items/<id>/{poster,poster-thumb,backdrop}.webp` and `$CACHE/files/<id>/still.webp`. URLs carry `?v=updatedAt` for cache busting. `poster.src`/`backdrop.src` record the link each came from, so a re-match with the same link doesn't download again (uploads and frame grabs remove them).
- **Everything pulled from the internet is cached on the server**; clients never fetch from third parties. Provider responses are in `provider_cache`; artwork as above; cast photos in `$CACHE/people/<id>.webp`, fetched on first request (`worker.PersonPhoto`); and any other remote image (channel logos, guide/recording/series art, the match picker's posters) goes through `GET /api/artwork/remote?u=` (`api/remote.go`), which fetches once into `$CACHE/remote/<sha256>`, only from allowlisted hosts (`remoteHosts`), and prunes images unused for 90 days. `db.ImageURL` fields marshal to those cache paths, so a new remote image field should use that type (or `db.CachedImage`). The Roku resolves them with `imageUrl()`.
- **Cast and crew** (TMDB only; tables `people`, `item_credits`, `db/credits.go`): `Details.Credits` holds the top 20 billed cast (TV: `aggregate_credits`) and key crew (`crewJobs`; TV: `created_by` as Creator), replaced on every match and dropped by `ClearMatch`. `GET /api/items/{id}` adds `cast`/`crew` (crew grouped per person); `GET /api/people/{id}` lists the library's titles a person is in, with their roles (`pages/PersonPage.tsx`, `components/Credits.tsx`). `POST /api/libraries/{id}/rematch` re-matches a whole library (Libraries → Re-match), keeping pins.
- **Profiles** (table `profiles`, `db/profiles.go`, `api/profiles.go`) are accounts (below). A profile is the signed-in account: `authenticate` puts its id in the request ctx (`db.WithProfile`). Per-profile data: `watch_state` (PK `profile_id, file_id`), `profile_channels` (favourites; `channels.pinned` is gone) and `prefs`, a JSON object owned by the UI and merged with `json_patch` via `PATCH /api/profiles/{id}/prefs`. Queries take the profile from ctx via `watchJoin(ctx)`, `fileFrom(ctx)`, `playFrom(ctx)`, `summaryCols(ctx)` and `channelCols(ctx)`, which format the int64 into the SQL so positional args don't shift. Background work has profile 0 and sees no watch state. Everything else (libraries, recordings, series rules, settings) is shared. Frontend: `stores/profile.ts` (`usePrefs`, `setPrefs`). `App` renders nothing until it loads. Switching profile does a full reload, because `useApi`'s cache holds the old profile's data. Live TV filters are stored in localStorage per profile.
- **Accounts** are always on (`internal/auth`, `api/auth.go`, `api/accounts.go`, `db/accounts.go`, migration 0013, web `stores/auth.ts`): a profile is the user (`password_hash` Argon2id via `auth.HashPassword`, `role` admin|user, `can_record`, `disabled`, `must_change_password`, `password_locked` (migration 0018: the account can't set or change its own password, `POST /api/auth/password` answers 403; admins are never locked, locking clears must-change, and an admin reset of a locked account isn't temporary)). Routes in `api.go` are grouped: open (`GET /auth`, login, refresh, setup, and artwork: posters, backdrops and stills, so TV image nodes need no token), signed in (`authenticate` + account routes), then `passwordCurrent`, with `userRoutes`, `recorderRoutes` (`recorders` middleware, plus `mayManage(ownerId)` in the handlers via `recordings.profile_id` / `series_rules.profile_id`) and `adminRoutes`. **Passwordless sign-in** (`api/passwordless.go`, setting `auth.passwordless`, decided once on first use: on unless a profile already had a password; `COUCHSIDE_AUTH=true` locks it off): `GET /api/auth` then lists `profiles`, and `POST /api/auth/pick` starts a session for a profile without a password (one with a password answers 401 `password_required`). Admins toggle it with `PUT /api/settings/passwordless`, which refuses to turn it off while no admin has a password. Migration 0016 makes the oldest profile admin. Accounts can be created without a password while passwordless is on, and `POST /api/accounts/{id}/password` with an empty password removes one. Access tokens are HMAC-signed (`auth.Signer`, key in `$DATA/auth.key`, 15 min for web, 12 h for TV clients, whose video players keep their headers) and carry the session id, checked against `sessions` through a 30s cache (`sessionCache`; forget it after changing a profile's role, password or status). Refresh tokens are stored as SHA-256 in `sessions.refresh_hash`, rotated by `RotateRefresh`; old hashes go to `session_used_tokens`, and reuse after the 60s cross-tab grace (409 `refresh_stale`) deletes the session. The web gets cookies: `couchside_access` (Lax, `/`), `couchside_refresh_<profile>` (Strict, `/api/auth`, one per signed-in profile so a browser can switch), and `couchside_profile` naming the active one; TV apps get JSON tokens and send Bearer. Cookie-authenticated writes must pass `sameOrigin`. Login throttling is `auth.Limiter` per IP and per name. A 500's text is shown only for `usererr` errors (`internal/usererr`, used for live TV and transcode messages written for users); anything else answers "internal error" and goes to the log, so return `usererr.New` for a message the UI should show. The setup code is printed when passwordless is off and there's no enabled admin with a password. `couchside reset-password [-admin] <name>` (`cmd/couchside/resetpassword.go`) is the recovery path. Frontend: `api()` refreshes once on a 401 and retries; `stores/auth.ts` renews 2 minutes before expiry (cookies also feed `<video>`, `<img>` and hls.js); `App` shows Setup, SignIn (the profile picker; a locked profile asks for its password) or ChangePassword pages before loading the profile and starting the status poll; `useIsAdmin`, `useCanRecord` and `useOwnerCheck` hide controls the server would refuse.
- **Search** (`GET /api/search?q=&limit=&kinds=`, `api/search.go`, `internal/search`, `db/search.go`): titles of items, episodes that have a file, channels (name, number, affiliate) and guide programs that haven't ended are held in an in-memory index rebuilt at most every 15s, and ranked in Go: exact, then space-less exact ("spiderman" = "Spider-Man"), prefix, every query word starting a title word, then a 3+ letter fragment. Normalization is `metadata.Normalize`. Hits are hydrated per profile as `ItemSummary`, `PlayInfo` (best file per episode) and `{program, channel}`. Web: the sidebar box (`/` focuses it) drives `/search?q=` (`pages/SearchPage.tsx`); the router keeps the query string in `path`.
- **LAN discovery** (`internal/discovery`, started from `main.runDiscovery`): an SSDP responder answers M-SEARCH for `urn:couchside-app:device:server:1` (and `ssdp:all`) with LOCATION `<base>/api/discovery` (open; id, name, version, sign-in mode) and `X-COUCHSIDE-*` headers. The base is the address the reply leaves from plus the HTTP port, or `COUCHSIDE_DISCOVERY_URL`. No NOTIFY announcements. The server id lives in `$DATA/server.id`. Containers need host networking for multicast (Helm `discovery.hostNetwork`). Failing to listen only logs a warning.
- **Frontend** uses a tiny history-API router (`stores/router.ts`), `useApi` for stale-while-revalidate fetches, and a zustand status store that polls `/api/status`. Grids are virtualised with @tanstack/react-virtual and manage their own scroll.

## Encoding (internal/transcode, worker/optimize.go, web PlayerPage)

- **Decision** happens client-side in `web/src/lib/playback.ts`. It uses canPlayType for direct play, then the optimized copy, then HLS. The server then decides copy vs encode per stream in `transcode.Manager.Create`. Video is copied only for 8-bit H.264 that isn't HDR and doesn't need downscaling.
- **HLS sessions**: the playlist is synthesized up front, with `SegDur` = 4s and every segment listed. Segments are generated on request. A request outside the current ffmpeg run restarts ffmpeg with `-ss N*4 -copyts -start_at_zero` and `-force_key_frames expr:gte(t,n_forced*4)`. `t` is relative to the run's first frame, so don't add the start offset. Remuxed segments follow source keyframes, which hls.js tolerates.
- ffmpeg is SIGSTOPped when more than 30 segments ahead and killed after 90s idle. Sessions expire after 3h and are wiped on start. At the limit, a session idle 20s or more is evicted. The limit counts sessions with a running ffmpeg or a request in the last 90s; it's checked and the slot taken under one hold of `Manager.mu` (probing happens before), and again when `Segment` has to start ffmpeg for a session that has none. `Session.restartMu` (taken before `mu`) serialises stop/start, and a closed session never starts again.
- **Optimize** jobs (`kind=optimize`) run in their own worker pool (`ClaimJob(ctx, encode=true)`), so scans are never blocked. Progress comes from `ffmpeg -progress pipe:1`. Cancel deletes the job row. Output goes to `$CACHE/optimized/<fileId>.mp4`. A changed file drops its optimized copy, and orphans are cleaned at startup.
- **Hardware**: `transcode.Detect` runs a one-frame test encode and falls back to software. For VAAPI it also tests the full GPU pipeline (`testHWDecode`: encode a clip on the GPU, then decode + `scale_vaapi` + encode it), setting `Encoder.HWDecode`, and `HWTonemap` when ffmpeg has `tonemap_vaapi`. With `HWDecode`, sessions use `vaapiFull` (`-hwaccel vaapi -hwaccel_output_format vaapi`, `scale_vaapi`, `tonemap_vaapi`, `h264_vaapi`), so 4K HEVC HDR never touches the CPU; without GPU tone mapping only the scaled frames are downloaded for zscale. A session whose GPU run fails falls back to CPU decode for good (`Session.gpuFallback`); burned-in subtitles always use the CPU path. Live TV uses the same GPU pipeline (`deinterlace_vaapi=auto=1`, `-bf 0`), retuning with CPU decoding if the GPU run fails before the first playlist; optimize still decodes on the CPU. Quality presets (`lib/playback.ts` `PRESETS`, Plex's ladder: 1080p 20/12/10/8, 720p 4/3/2, 480p 1.5, 360p 0.7 Mbps) send `bitrateK` with the height to `POST /api/files/{id}/hls`. On Intel iGPUs use VAAPI (the iHD driver is in the image) with `/dev/dri` mounted, a privileged container (or a GPU device plugin), and `supplementalGroups` set to the host gids of `/dev/dri/renderD128` and `card*`.
- **Player UI** is `web/src/components/player`. `PlayerFrame` owns the `<video>`, controls, keyboard, auto-hide and full screen (on its root, which is `data-theme="dark"`). `SettingsMenu` takes `SettingSection[]`, and `useMediaState` snapshots the video. Pages (`PlayerPage`, `LivePlayerPage`, `RecordingPlayerPage`) only own sources and settings. Timelines are `vod`, `live` (seekable range, GO LIVE via `hls.liveSyncPosition`; the bar spans the guide program the playhead is in (or its half-hour slot when the guide has none), in clock time where the live edge is now, with the time before tune-in hatched and unseekable via SeekBar `availableStart`), or `recording` (wall-clock start/end, with a hatched unrecorded part).
- **Tracks**: `GET /api/files/{id}/streams` lists audio and subtitles, including sidecars (`x<N>` keys). `GET /api/files/{id}/subtitles/{s|x}<N>.vtt` converts to WebVTT, cached as `$CACHE/subs/<file>-<key>-<mtime>.vtt`. Embedded tracks are fetched by the player in 90s chunks (`s<N>.c<K>.vtt`), because a whole track means reading the entire file: 7 minutes for a 30 GB remux over SMB, versus about 7s per chunk. Chunks use `-ss from -copyts -start_at_zero … -to <absolute end>`, since an input `-t` is ignored with copyts. The player dedupes cues across chunk overlaps. HLS sessions take `audioIndex` (`-map 0:a:N`) and `burnSubtitle`. Burn-in uses `-filter_complex [1:s:N][0:v:0]scale2ref=w=main_w:h=main_h…overlay` with a **second input seeked 10s earlier**, because PGS captions need earlier data. ffmpeg 6.1's scale2ref uses `main_w`/`main_h`, not `rw`. `Encoder.VideoParts` returns the bare filter chain for this.
- Test media for the tricky paths: HEVC 10-bit + AC3 in MKV (transcode), H.264 in MKV (remux), and HEVC tagged smpte2084 (tone map). Generate them with ffmpeg lavfi.

## Live TV & DVR (internal/livetv, web components/livetv, LivePlayerPage)

- It's off unless `COUCHSIDE_HDHOMERUN` is set. The HDHomeRun HTTP API supplies `discover.json`, `lineup.json` and `status.json`. Stream URLs come from the lineup (`:5004/auto/v<ch>`), and HTTP 503 means every tuner is busy.
- **Guide**: `api.hdhomerun.com/api/guide.php?DeviceAuth=...&Start=<unix>`, about 4h per page, paged to about 26h. It **rejects Go's default User-Agent with 403**, so keep the explicit UA. DeviceAuth rotates, so re-read `discover.json` before each fetch and never expose it.
- **Channel prefs**: `channels.pinned` (via `PUT /api/livetv/channels/{n}/pin`) sorts first in `Channels()`. `signal_strength`/`signal_quality` come from the lineup's scan readings on each refresh. `ReplaceChannels` upserts, so pins survive lineup refreshes. Filtering is client-side, in `components/livetv/filters.ts` and `FilterBar.tsx`, with state shared by the Guide and Channels tabs and kept in localStorage.
- **Live passthrough**: `POST /api/livetv/watch` (and recording watch) take `videoCodecs`/`audioCodecs`, the codecs the client decodes (`livetv.NormalizeCodec` names: mpeg2, h264, hevc, ac3, eac3, aac). When the channel's lineup codecs are in them, `Spec.CopyVideo`/`CopyAudio` repackage the broadcast into HLS with `-c copy` (segments cut at its own keyframes; the client deinterlaces). The Roku sends what `roDeviceInfo.CanDecodeVideo/Audio` allow unless the profile pref `livePassthrough` is false; browsers never do. Sessions are shared per channel + height + copy flags.
- **Live**: one ffmpeg per channel and height, shared by viewers; concurrent tunes of the same stream wait for one start (`liveManager.starting`). Heights snap to the presets (`snapHeight`: 360/480/720/1080), and streams that convert video are capped at `COUCHSIDE_MAX_TRANSCODES` (`ErrBusyEncoding`, 429); passthrough isn't counted. Tuner streams keep a 3-hour sliding window of 2s segments (`liveWindow`, `delete_segments`); recordings watched from the start keep an EVENT playlist. It deinterlaces with yadif (interlaced frames only), and waits for the first playlist before returning. It's reaped 20s after the last request. libx264 runs with `-tune zerolatency` (`VideoOpts.Live`) so segments arrive evenly. The player sits 8s behind the edge (`liveSyncDuration`, no playback-rate catch-up) and `useLiveCushion` holds playback until 6s are buffered, at the start and after any stall, instead of stuttering at the edge. It measures encoder speed from playlist growth (LEVEL_UPDATED `totalduration` over wall time) and warns below 0.95×.
- **Recordings folder**: the `settings` table key `dvr.recordings_dir` overrides `COUCHSIDE_RECORDINGS_DIR`; always call `Service.RecordingsDir(ctx)`, never `cfg.RecordingsDir`. `pathInDir` reuses a matching show folder (by `parse.Name` plus `Normalize`) and season folder. `ensureLibrary` uses the library that *contains* the folder, and only creates "DVR Recordings" when none does. Delete only removes the row's own `.ts` file, because the folder may be a shared TV library. The media mount is read-write for this; nothing else writes there.
- **Shutdown during a recording** leaves the `.partN.ts` files and the `recording` status alone. `recoverInterrupted` resumes into the same path, via `existingParts`, which also picks up a finished file from older builds, and joins everything at the end. Never finalize on `parent.Err()`, or the file splits in two.
- **Watch from start**: `POST /api/dvr/recordings/{id}/watch` runs a live-style HLS session whose input is the growing part file (`-follow 1`). The player uses `startPosition: 0`.
- **Padding**: `Service.Padding(ctx)` reads `dvr.pad_before`/`dvr.pad_after` (seconds, set in Settings via `PUT /api/settings/timing`), falling back to `COUCHSIDE_DVR_PAD_BEFORE/AFTER` (default 10s). Each recording row stores its own pads; saving new padding also updates rows still `scheduled`.
- **Recording**: the scheduler ticks every 5s. It runs `ffmpeg -c copy -t <remaining>` into `.partN.ts`, retries on drops, and joins parts with `concat:`. Plex-style names are built in `recordingName`; the file is picked in `startRecording` under `pathMu`, after the series lookup. Due recordings start on their own goroutines (`starting`), and `MarkRecording` only moves a row that is still `scheduled`. Restart recovery lives in `recoverInterrupted`. Each finished recording enqueues a scan of the auto-created "DVR Recordings" library, and `underRoot` allows the recordings dir outside `MEDIA_ROOT`.
- **Series rules** (`livetv/rules.go`, table `series_rules`) are keyed by the guide's SeriesID. `evaluateRule` walks upcoming airings and handles the cases in this order:
  - DRM and channel filter.
  - An existing recording at that airing: cancelled ones are never revived, and failed ones can be retried.
  - The mode.
  - The library check (`LibraryEpisodeKeys`) and the recorded check (`RecordedEpisodes`).
  - Same-episode repeats.
  - Tuner conflicts: skip this airing, and a later one can take the episode.

  Episode keys are `S11E4` (unpadded), or `t:<normalized show>|<normalized episode title>`. Rule-owned scheduled rows the rule no longer wants are deleted (`UnscheduleStale`), except anything starting within 30s. `LibraryMatchesFor` ranks same-titled shows by matching upcoming episode titles. Keep-last-N runs in `afterRecording`. Tests in `livetv/rules_test.go` run on a temp SQLite DB.
- **Same-titled series** (`livetv/identify.go`, `metadata/identify.go`, table `series_matches`): `showYear` identifies a recording's series with `metadata.IdentifySeries`. A single exact-title OMDb series wins; otherwise the program's `original_airdate` must fall in a series' run (±1 year); otherwise the season's episodes decide (title, or release within 2 days). The year is used only when `Shared` (another series has the title), so it goes into the show folder (`MacGyver (2016)`), which the parser and matcher already read. Results are stored per guide SeriesID: unknown ones are rechecked after 7 days, known ones after 30. Lookups are prefetched when a recording is scheduled (`prefetchShow`, from `Record` and rules) and done at start with an 8s timeout; a failure records under the plain name. `pathInDir` won't reuse a same-titled folder with another year, or a plain folder whose matched item (`FolderSeriesYear`) has another year.
- **Library Manage view** (`/libraries/{id}`, `pages/LibraryManagePage.tsx`, `components/manage/`, `api/manage.go`, `db/manage.go`) is one table per library. `ManageRows` gives max/min file height, codec, size, distinct episodes and `sameImdb`; duplicates are extra files per movie or episode, or items sharing an IMDb id. Deletes remove files **on disk**: `deleteFiles` refuses paths outside the library folder (`insideDir`), removes subtitle sidecars, cache (optimized, still, item art) and DVR recording rows, then `DeleteFileRows` drops orphan items and episodes. `removeEmptyDirs` stops at the library root and reports folders that still hold non-video files. Uploaded artwork (`PUT /api/items/{id}/artwork/{poster|backdrop}`, raw body) sets `media_items.custom_poster`/`custom_backdrop`, which the artwork job and `ClearMatch` respect. Match search is `GET /api/items/{id}/lookup` (`Chain.SearchTitles`; an IMDb id or URL looks up directly), and picking a result reuses `POST /api/items/{id}/match`.
- **Commercials** (`worker/commercials.go`, table `commercials`): `indexFile` queues a `commercials` job for a file whose path is a completed recording (`IsRecording`) and has no current result. The job runs `comskip --ini --output=<tmp> --output-filename=couchside` and parses the `.edl`. comskip may exit 1 on success or on error, so a missing `.edl` tells them apart. Results store the file's size and mtime and are ignored once the file changes. The default ini is written to `$CACHE/comskip/comskip.ini`. It's off when `COUCHSIDE_COMSKIP` isn't on PATH. The Dockerfile builds comskip V0.83 from source with a static argtable2, because Alpine 3.22 has neither. `POST /api/items/{id}/commercials` (`{"redo"}`, admin) queues a whole series or movie via `db.CommercialCandidates` (playable, non-extra files without a current result, or all with redo); the title page's "⋯" `MoreActions` menu (`MenuButton` in `components/ui.tsx`) calls it when `status.comskip` is true. In the player, `useBreakSkip` auto-skips, except for breaks the viewer seeked into (`allow`). The mode is the profile pref `commercials`. `GET /api/files/{id}/commercials` returns breaks already trimmed by the shared settings `commercials.skip_after_start` / `skip_before_end` (default 1s each, `api/timing.go`), so skips never cut into the show; breaks left under 1s are dropped. Before trimming, breaks less than `commercials.merge_gap` apart (default 60s) are joined, since comskip often splits a break around a promo it took for show; this applies at read time, so existing results benefit. The default ini (`defaultComskipINI`) keeps comskip's detection defaults except `logo_percentage_threshold=0.5` (default 0.25): a block with the logo up longer than that is scored as show, which kept logo-bearing promos at the ends of breaks. Ini changes only reach a file when it's checked again.
- Tuners can be shared with other DVRs (e.g. Plex). ATSC 3.0 channels with DRM (HEVC/AC-4) are listed but shown locked.
- **Virtual channels** (`livetv/virtual.go`, `virtual_stream.go`, `db/virtual.go`, `api/virtual.go`, migration 0017; web `components/settings/VirtualChannels.tsx` and `ChannelEditor.tsx`): Couchside's own channels from the library. Each has a `channels` row with `virtual_id` set (`Channel.Virtual`), so guide, lineup, favourites, search and both players treat it like a tuner channel; `ReplaceChannels` never touches those rows. `VirtualConfig` (JSON in `virtual_channels.config`) holds the filters, order (shuffle deck or sequential round-robin per show, kept in `state`) and `Filler` (a folder of clips, lengths cached in `filler_clips`; align to 15/30/60 min, padding at most 10 min; mid-program breaks). `extendVirtual` (serialized by `virtualMu`) appends `virtual_playout` pieces (ms, path, in-point, filler flag) and their guide `programs` 36h ahead, every 10 min; a program covers its own commercials. Streaming (`startVirtual`) is on demand: one ffmpeg per piece (`-ss in -t dur`, `-re` except a fast first run that gives the player 8s of buffer, `-output_ts_offset` so timestamps continue, `anullsrc` for files without audio), merged by `mergedPlaylist` into a sliding 30-min `index.m3u8` with discontinuities. The Live TV service now always exists: `HasTuner()` gates tuner-only features (refresh, DVR folder, rules, padding); `configured` is tuner or any virtual channel. Virtual channels can't be recorded.

## Styling

- Colours: `docs/style.md` (tokens, contrast, rules). One dark theme, "seafoam as the primary": neutral dark grey surfaces, bright seafoam `--accent` as the only interactive colour, the logo's blue (`--good`) and sky (`--info`) for state, red (`--critical`) for recording, errors and favourites, amber warnings. There is no light theme (no theme store or toggle). Bright fills take `text-on-accent` (deep green), never `text-white`. Violet (`--secondary`), `--brand-pink` and `--brand-cyan` are avatar colours only.
- `web/src/index.css` starts from Portside Lite's component classes (`.card`, `.btn-*`, `.field`, `.navtab`, `.table`, `.tint-*`). Media additions follow the same naming: `.poster`, `.still`, `.row-title`, `.art-badge`, `.chip`, `.hero-fade`, `.poster-placeholder`.
- Put new reusable styles in `index.css` under `@layer components`. Don't hard-code colours; use the tokens.
- **Actions that can fail** go through `attempt("Couldn't …", fn)` (`lib/notices.ts`), which shows the server's message in a `.notice` (rendered by `components/Notices.tsx`, over everything). Modal dialogs use `useDialog(ref, onClose)` (`lib/dialog.ts`: focus in, Tab trapped, Escape, focus back) with `role="dialog" aria-modal="true"`.
- **Phones** (below `md`, `usePhone()` in `lib/media.ts`): `Sidebar` and `StatusBar` hide, and `MobileNav` shows a top bar (logo, search, profile) and bottom tabs (Home, Movies, TV, Live TV, More); the More sheet holds Activity, Libraries, Settings, profile and sign-out. Page side margins use `.gutter` (16px, 24px from md); `PosterGrid` fits three across. List pages put search first, with the rest in `FilterMenu` (a bottom sheet on phones, a dropdown on desktop) and active filters as removable `.choice` chips.
